# 실제 모델 연결과 RAG 개선

> **최신 개선:** 실제 로컬 모니터링, 원문 단계·의미 검증, 복합 증상 검색, 기록 복원·실행 재개, 토큰/비용 표시를 추가했습니다. [남은 한계 개선과 현재 동작](/Users/user/mini-project/all_total_vue_student/doc/archive/REMAINING_LIMITS.md)에서 확인하세요. 아래의 이전 개선 단계 설명과 실측은 당시 기록입니다.

## 1. 설정 파일 이름부터 정리

처음 프로젝트에는 **`.env.example`만 있었고, 사용자가 그 파일에 실제 키를 입력한 상태**였습니다. 실행 코드는 `.env`를 읽으므로 그 상태로는 키가 자동 적용되지 않았습니다.

현재는 다음처럼 정리했습니다.

| 파일 | 현재 역할 |
| --- | --- |
| `.env` | 입력했던 실제 설정을 보존한 실행용 파일. Git에서 제외하며 파일 권한은 소유자 읽기·쓰기만 허용 |
| `.env.example` | 키 값이 비어 있는 공유용 설정 양식 |

키 값은 설명서·검증 결과·실행 로그에 출력하지 않았습니다. `.env`의 키 유무와 실제 호출 성공은 별도로 확인했습니다.

## 2. 무엇을 실제로 연결했나

| 역할 | 실제 사용 모델 | 확인 내용 |
| --- | --- | --- |
| OpenAI 분류·계획 | `gpt-4o-mini` | 실제 응답, 구조화 출력, 사용 토큰, 토큰 스트림 |
| OpenAI 보고서 작성 | `gpt-4o` | 실제 응답과 출처를 포함한 보고서 |
| Ollama 분류·계획 | `qwen3.5:2b` | 설치 모델 확인, 실제 응답·구조화 출력 |
| Ollama 보고서 작성 | `qwen3:8b` | 실제 응답과 출처를 포함한 보고서 |
| RAG 의미 임베딩 | 로컬 `qwen3-embedding:0.6b` | 실제 벡터 생성과 런북 검색 |

화면의 **답변 모델** 선택으로 OpenAI·Ollama·데모를 바꿀 수 있습니다. 대화 요청마다 선택한 모델의 그래프를 사용하며, MCP와 대화 저장소는 공유합니다. 기본값은 `.env`의 `LLM_BACKEND`입니다.

기본 RAG 임베딩은 로컬 Ollama입니다. 따라서 OpenAI로 답변하더라도 문서 벡터 생성은 로컬에서 수행합니다. `RAG_EMBEDDING_BACKEND=openai` 설정도 구현되어 있지만, 이번 임베딩 실측은 로컬 모델 기준입니다.

## 3. 키워드 선택에서 의미 검색으로

```text
기존
모든 시스템의 알림을 합침
  → 처음 일치한 키워드 하나 선택
  → 대응 매뉴얼 하나 조회

현재
시스템별 관측 알림 + 사용자 증상
  → 질문을 임베딩 벡터로 변환
  → 런북 벡터들과 유사도 비교
  → 시스템별 관련 문서 조회
  → 원문·문서 ID·출처를 보고서 작성에 제공
```

예를 들어 결제 서비스의 CPU 문제와 캐시 서비스의 메모리 문제가 함께 있으면, 각 시스템별로 검색해 CPU 대응·메모리 대응 자료를 함께 제공합니다.

문서를 무조건 두 개씩 넣으면 무관한 자료가 섞일 수 있어, 기본값은 **시스템별 최상위 청크 1개**로 설정했습니다. `.env`의 `RAG_TOP_K`로 바꿀 수 있습니다. 한 시스템에 여러 장애가 동시에 있는 경우에는 이 값과 검색 설계를 재검토해야 합니다.

## 4. RAG 내부 동작

1. `data/runbooks/*.md`에서 제목과 본문을 읽습니다.
2. 긴 문서는 문맥이 겹치도록 나눕니다. 현재 런북 6개는 짧아 대부분 한 청크입니다.
3. 로컬 임베딩 모델로 문서 벡터를 만듭니다.
4. `data/rag_index.sqlite3`에 벡터를 캐시합니다.
5. 질의 벡터와 문서 벡터의 코사인 유사도로 검색합니다.
6. 문서 ID, 제목, 파일 경로, 유사도, 본문을 반환합니다.

캐시 키에는 임베딩 제공자·모델·문서 내용이 들어갑니다. 내용이 바뀌면 새 벡터를 생성하고, 이전 문서 내용은 검색 대상에서 제외합니다. 서버 재시작마다 전체 문서를 다시 임베딩하지 않습니다.

현재처럼 문서가 적을 때는 SQLite에 벡터를 저장하고 Python에서 전체 비교하는 방식으로 충분합니다. 문서가 많아지면 전용 벡터 인덱스와 검색 시간 검토가 필요합니다.

`local` 임베딩 설정은 네트워크 없는 자동 검사용 문자 해시 벡터입니다. **학습된 의미 임베딩이 아니며**, 실제 서비스는 `ollama` 또는 `openai`를 사용합니다.

## 5. 답변 품질을 위해 함께 바꾼 것

### 현재 수치와 생성 문장을 분리

실제 Ollama 시험에서 모델이 알림 문자열에 들어 있는 고정 수치를 현재 측정값으로 인용하는 문제가 발생했습니다. 검증기를 느슨하게 하는 대신 다음처럼 수정했습니다.

- 현재 CPU·메모리 표시는 코드가 모니터링 원본 값으로 구성합니다.
- 모델 입력의 알림 요지에서는 백분율을 생략해 현재 측정값과의 혼동을 줄입니다. 원본 모니터링 데이터는 보존합니다.
- 모델은 원인 후보, 대응 절차, 추가 확인 항목을 JSON 구조로 작성합니다.
- 코드는 JSON을 `1) 관측 정보 → 2) 원인 후보와 대응 → 3) 추가 확인` 형식으로 표시합니다.
- 생성 문장에 추가된 CPU·메모리 수치도 기존 검증기로 대조합니다.

### 출처를 표시하고 확인

검색 결과에는 `[RB:cpu-spike:1]` 같은 출처 ID가 붙습니다. 모델이 대응 절차에 출처를 달도록 하고, 조회하지 않은 출처나 출처 없는 대응 답변은 반려합니다. 화면에도 조회한 문서 제목과 파일 경로를 표시합니다.

이 검사는 **출처가 실제 조회 목록에 있는지** 확인합니다. 그 출처가 문장의 모든 의미를 완전히 뒷받침하는지까지 증명하지는 않습니다.

### 호출·계획·오류 처리

- 실제 모델의 분류·계획·분석·대화·보고서 호출을 비동기 HTTP로 통일했습니다.
- OpenAI의 SSE와 Ollama의 NDJSON 응답을 처리합니다. 일반 대화는 토큰을 화면에 중계합니다.
- 장애 보고서는 검증 전 노출을 막기 위해 구조화 생성과 검증을 기다립니다.
- 실제 모델의 계획에서 일부 요청 대상이 빠져도 명시된 알려진 시스템을 모두 보완합니다.
- 명시한 미등록 시스템은 다른 시스템으로 바꾸어 조사하지 않고 대상 확인을 요청합니다.
- 개별 자료 조회가 실패해도 성공한 결과를 유지하고 진행 이벤트에 실패를 표시합니다.
- 교육용 고정 지연을 제거했고, 최초 타임아웃 시뮬레이션은 설정으로 켤 수 있게 했습니다.

## 6. 실행 방법

프로젝트 폴더에서 실행합니다.

```bash
bash sh/run_live.sh
```

화면: [http://localhost:8600](http://localhost:8600)

Ollama 서버가 실행 중이고 설정한 채팅·임베딩 모델이 설치되어 있어야 합니다. 현재 컴퓨터에서는 설치와 실제 응답을 확인했습니다. OpenAI는 `.env`에 설정한 키를 사용하며 실제 요청에 따른 요금이 발생합니다.

이 실행기는 다른 프로그램을 강제 종료하지 않습니다. 포트를 사용 중이면 안내 후 멈추며, Ctrl+C로 종료할 때 자신이 실행한 서버만 정리합니다. 대화 DB는 보존합니다.

기존 모델별 백엔드 실행 명령도 같은 실행기로 연결했습니다.

```bash
bash sh/run_agent_openai.sh
bash sh/run_agent_ollma.sh
```

위 두 명령은 백엔드만 실행합니다. 화면 서버는 별도로 실행해야 합니다. `run_live.sh`는 둘을 함께 실행합니다.

한 번의 실행 기록이며 평균·보장 성능은 아닙니다. 로컬 자원 상태, 모델 적재·캐시, 네트워크와 출력 길이에 따라 달라집니다. 두 시험의 샘플 모니터링 수치에는 난수 변동이 있어 답변의 동일 수치 비교 실험으로 해석하면 안 됩니다.

### 문서 검색 비교

수동 작성 사례 12개에 동일한 증상·관측 자료를 넣었습니다.

| 지표 | 기존 단일 키워드 규칙 | 시스템별 RAG 검색 |
| --- | ---: | ---: |
| 필요한 문서 유형의 평균 회수율 | 66.7% | 100% |
| 필요한 문서 유형과 정확히 일치한 사례 비율 | 50% | 100% |

문서 6개·수동 사례 12개에 대한 작은 회귀 평가입니다. 검색 설정을 조정하면서 사용한 사례이므로 독립적인 최종 평가셋은 아닙니다. 실제 운영에서의 검색·답변 정확도를 보장하지 않습니다. 답변 문장의 의미적 정확도 향상은 별도 평가가 필요합니다.

기존 검사를 포함해 자동 검사 **28개**를 통과했습니다. 실제 네트워크를 사용하는 확인과, 외부 연결 없는 회귀 검사를 구분했습니다.
