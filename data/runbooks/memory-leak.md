# Runbook: 메모리 누수(Memory Leak) 대응 절차

1. get_monitoring_status로 현재 시스템 메모리 사용률과 요청 시점에 저장된 최근 표본을 확인한다. 정기 수집 이력이 아니므로 지속 증가나 메모리 누수를 확정하지 않는다.
2. 담당자가 해당 프로세스 또는 컨테이너의 메모리 사용률이 90% 이상이고 OOM 위험이 임박했음을 별도 확인한 경우에만 재시작을 검토한다. 시스템 전체 메모리 사용률을 프로세스 사용률로 대체하지 않는다. 재시작은 임시 조치임을 기록한다.
3. 힙 덤프 또는 프로파일링 도구로 어떤 객체가 계속 쌓이는지 확인한다.
4. 캐시 무제한 증가, 커넥션 미반환, 이벤트 리스너 중복 등록 같은 패턴이 최근 배포에 있었는지 점검한다.
5. 원인이 된 배포가 있으면 롤백하고, 컨테이너 메모리 상한선을 재확인해 재발 시 더 빨리 감지되도록 조정한다.
